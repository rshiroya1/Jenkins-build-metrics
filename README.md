# Jenkins Build Metrics

A small DevOps metrics tool that parses Jenkins build data and outputs **average build time**, **failure rate**, and the **flakiest job** to raise awareness of pipeline health.

## What it shows

| Metric | Description |
|--------|-------------|
| **Average build time** | Mean duration of all builds (seconds) |
| **Failure rate** | Percentage of builds that failed (excludes UNSTABLE) |
| **Flakiest job** | Job with the most failures (and its failure rate) |

## Files

```
Jenkins-build-metrics/
├── parse_logs.py      # Parses build logs, computes metrics, writes metrics.json
├── metrics.json       # Output: metrics (generated by parse_logs.py)
├── sample_builds.json # Sample input for trying the script
└── README.md          # This file
```

## Input format

`parse_logs.py` expects a **JSON file** with a list of build records. Each record can look like:

- From Jenkins API / typical export:
  - `job` (or `name` / `jobName`)
  - `duration` or `durationInMillis` (milliseconds)
  - `result` or `status`: `SUCCESS`, `FAILURE`, `UNSTABLE`, etc.

Example:

```json
[
  { "job": "backend-api", "duration": 120000, "result": "SUCCESS" },
  { "job": "frontend", "duration": 45000, "result": "FAILURE" }
]
```

You can export builds from Jenkins (e.g. via API or a plugin) and save as JSON, then point the script at that file.

## Usage

1. **Using sample data:**
   ```bash
   python parse_logs.py
   ```
   or on Windows: `py -3 parse_logs.py`

2. **Using your own build log JSON:**
   ```bash
   python parse_logs.py path/to/your_builds.json
   ```

3. **Custom output path:**
   ```bash
   python parse_logs.py path/to/builds.json -o path/to/metrics.json
   ```

## Output: `metrics.json`

Example after running:

```json
{
  "average_build_time_seconds": 152.1,
  "failure_rate_percent": 33.3,
  "total_builds": 6,
  "flakiest_job": {
    "job": "e2e-tests",
    "failures": 2,
    "total_builds": 2,
    "failure_rate_percent": 100.0
  },
  "by_job": {
    "backend-api": { "total_builds": 2, "failures": 1, "failure_rate_percent": 50.0, "avg_build_time_seconds": 107.5 },
    "frontend": { ... },
    "e2e-tests": { ... }
  }
}
```

Use this file in a dashboard, Slack bot, or CI step to track build health over time.

## Requirements

- Python 3.10+ (for `list[dict]` type hints; works on 3.9 if you change to `List[dict]` and import from `typing`).
